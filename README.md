# Pocket Billies: Gotta tax 'em all! — 0.1.0 alpha

A classic RPG inside the Hollow Earth, where the Billies are the wildlife. You walk the seamless maps yourself with a
joystick, step into rooms that are bigger on the inside, battle, make friends, and edit everything in
**Pocket Billies Studio**.

0.1.0 alpha is a fresh base: numbering starts over here and old saves don't carry over. What changes from release to
release is in [CHANGELOG.md](CHANGELOG.md); where the game is going is in [docs/VISION.md](docs/VISION.md). The earlier
build (Net Worth, then Pocket Billies alpha 0.1 to 0.5) is kept on the `legacy` branch, and its changelog in
[docs/archive/LEGACY-CHANGELOG.md](docs/archive/LEGACY-CHANGELOG.md).

## Play

Open **https://nojiroh.github.io/pocket-billies/** in a browser with WebGL 2 (any recent phone or computer). On a
phone, add it to your home screen and it opens like an app and works offline.

Saves stay in that browser. Settings → Export save / Import save moves a save between browsers or devices; signing in
with a Google account keeps it online.

## Sending a debug log

If something looks wrong or runs slowly, open **Settings** (the gear) and use:
- **Run the full test**: about nine minutes on a phone (every place and room, then battles, the map, the opening, the
  dressing room and shops, then a stress test). A table marks each part OK or Problem. Your save isn't changed.
- **Run the diagnostics test**: about two minutes, for when the game runs slowly. It ends with **Save the report**, a
  short `pocket-billies-diagnostics-….json` to send.
- **Export debug log**: one `.json` file with frame rates per screen and scene, slow frames, errors, loading times,
  your device and graphics chip, and a small picture of the scene. It contains no save data, names or step history.

All three are also in the debug menu (add `?debug` to the address).

## Run it from the source

You need [Node.js](https://nodejs.org/) 22 or newer.

```sh
npm install        # once: Vite, ESLint, Prettier, Ajv
npm run dev        # the game at http://localhost:5173/game/, the Studio at /studio/
npm run build      # the site in dist/ (game/, studio/ and the start page; each page's modules in one file)
npm run preview    # serve dist/ to try the build
npm run data       # make game/data/gamedata.js from the data files (dev, build and the quick check do it too)
```

Don't open `game/index.html` straight from disk: the game needs a web server. Any static server of the repository
root works too (`python3 -m http.server`, then open `/game/`); run `npm run data` first, or the game reads the data
files one by one (slower). To try it on a phone on the same Wi-Fi, run `npm run dev -- --host` and open the address
it prints.

GitHub Pages is deployed from the build by `.github/workflows/pages.yml` (repository Settings → Pages → Source:
GitHub Actions).

## Pocket Billies Studio

The editor for the game's data, skeletons and art, at **https://nojiroh.github.io/pocket-billies/studio/** (or
`/studio/` on `npm run dev`). Admins sign in with a GitHub token; **Save to game** opens a pull request with the
changes, and the game changes once it is merged. What each section does is in [docs/STUDIO.md](docs/STUDIO.md).

## Contribute

The game is plain JavaScript with a custom WebGL 2 renderer. The code is ES modules, listed in order in
`game/index.html` (the Studio's in `studio/index.html`). The top of each module, between the `to-module` markers, is
generated by `npm run modules` (`tools/to-module.mjs`): run it after you add a top-level name or use one from another
file. A module imports what it uses from earlier modules directly, and what it uses from a later module (or from
whichever module the page has, for the renderer shared with the Studio) from `game/js/hooks.js`, which the declaring
module fills in; that keeps the page order. An imported name can't be assigned: a module that replaces another's
function or value calls that module's setter (`setS`, `setDioData`, ...), which also updates `hooks.js`. The debug
log reaches the modules through `game/js/debug-log-names.js` (generated too). Module names are not on `window`; the checks
put them there for their `page.evaluate()` calls (`window.PB_TEST_GLOBALS = true`, `game/js/test-globals.js`), and so
does `?globals` in the address, for the console. A few scripts stay classic on purpose and run first: `version.js`, `debug-log.js` and `tap-debug.js` (they catch errors even if the modules fail to load), the art
manifests, the data (`gamedata.js`, `data-files.js`, `data-fallback.js`).

Before you push:

```sh
npm run lint            # ESLint: undefined names (a module name used without an import), a name defined twice, likely bugs
npm run check:modules   # the modules' generated parts are up to date and the load order holds (npm run modules fixes them)
npm run format          # Prettier (npm run format:check only checks)
npm run check:data      # the game data: files, schemas, what refers to what (a second)
npm run check:smoke     # the quick check's smoke set, about two minutes
```

The quick check drives the game in headless Chromium. It needs Python 3 and
`pip install -r tools/requirements-check.txt && python3 -m playwright install chromium`. `npm run check:quick` is
the full check (about 40 minutes); results and pictures go to `validation/quick/`. GitHub runs lint, the format
check, the data check, the build, smoke and the Firestore rules tests on every push and pull request, and the full
check nightly.

Conventions: one rename per commit and never mixed with a behaviour change; reformatting only in separate no-op
commits (listed in `.git-blame-ignore-revs`); names follow [docs/NAMING.md](docs/NAMING.md). The plan of work is in
[docs/ROADMAP.md](docs/ROADMAP.md) and [docs/phases/](docs/phases/); [docs/HANDOFF.md](docs/HANDOFF.md) says where it
stands.

## Project layout

- `game/`: the game. `index.html` (the script order; the build replaces the module tags with one bundle), `version.js` (the version, the only place it is written),
  `sw.js` (offline cache), `css/`, `fonts/` (SIL Open Font License).
  - `data/`: all game data and rules as JSON files, edited by the Studio (or by hand). `index.json` lists them;
    a file per map (`scenes/`), Billie line (`lines/`), trainer (`trainers/`) and person (`people/`), and one file
    per other section (`moves.json`, `rules.json`, `route.json`, `scenery.json`...). `schema/` has their JSON
    schemas. `gamedata.js` is generated from them (not in git): everything but the maps' ground and props, which the
    game fetches from each map's file when it needs it (`js/map-files.js`).
  - `art/`: pictures, `manifest.js` (atlas rectangles), `next/rigs-next.js` (skeletons).
  - `js/`: the code. `game-data.js` builds everything from the data file; `boot.js` loading; `ui.js` the screens;
    `battle.js` battle rules and HUD; `seamless-world.js` walking from one place into the next; `walk-view.js` the walk scene's data and logic and
    `walk-view-gl.js` draws it; `engine/` the 3D engine (settings, WebGL setup, light, post effects); `battle-3d.js`,
    `world-map-gl.js` battles and the world map on the engine; `buildings.js`, `structures.js`, `solid-props.js`, `prop-models.js`
    3D buildings and props; `debug-log.js` the debug log; `self-test.js` the full test; `debug-menu.js` the debug menu;
    generated by `tools/to-module.mjs`: `hooks.js` (names from later modules), `debug-log-names.js` (what the debug log
    reads); `test-globals.js` puts the modules' names on `window` for the checks.
- `studio/`: Pocket Billies Studio. It imports the game's renderer modules from `../game/js/`.
- `firebase/`: the Firestore security rules and their tests (`cd firebase && npm ci && npm test`).
- `tools/`: `check-quick.py` (the quick check), `check-data.mjs` and `check-data-text.py` (the data checks),
  `build-data.mjs` (makes `gamedata.js`), `to-module.mjs` (the modules' generated imports, `hooks.js` and `debug-log-names.js`), `gamedata.py` (the data for Python tools), and the Python scripts that drew
  the art and built the scenes (the top of each says what it writes).
- `docs/`: vision, roadmap, phases, naming, security review, handoff log, the Studio guide.
